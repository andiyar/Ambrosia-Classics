# Ferazel's Wand RE bank — review 2026-10-03 (Fable reviewer, read-only pass)

VERDICT: ACCEPT_WITH_FIXES — every replica-critical HIGH claim (save layout, frame cap, physics
constants, type→class table, "physics table never read", `Mlvl` layout, census) survived raw
PowerPC disassembly and independent data decodes; the fixes are one mis-named save flag with
replica impact, one undocumented field rewrite the statue mechanic depends on, a coverage gap for
the non-enemy sprite physics the prompt asked for, and a handful of label/decode slips.

## Findings (most severe first)

1. **Important · confidence HIGH** · `engine.md` §9 (G layout) and §6, `world-data-format.md` §4.
   Bank: `G+0x176 + 2·L` = "level completed[100]". Found: `.SavePointSave @ 1000c104` also sets it
   to 1 at every checkpoint save — raw `1000c1b4 lha r0,0x0(r28)` … `1000c1c0 sth r5,0x176(r3)`
   with `r5 = 1` (decompile `*(undefined2 *)(iVar6 + *psVar2 * 2 + 0x176) = 1`), same in
   `.EndLevelSGUpdate`. The flag means "checkpointed or completed". Replica impact: `.SetupLevel
   @ 1000430c` branches on it (`== 1` → restore the record snapshot and keep counters; else reset
   `G+0x306/0x3ce/0x496` and recount totals), and `.GameLoop` gates the chapter screen on it. A
   replica that sets it only on completion resets the stats and skips the restore after a
   checkpoint resume.

2. **Important · confidence HIGH** · `physics.md` (whole file), INDEX NOT-RESOLVED list.
   Missing coverage the prompt required ("physics"): the player's interactions with non-enemy
   sprite classes are neither described nor listed as open. Never mentioned anywhere in the bank:
   `.RopeCollide` (128 lines, called at `.HandlePlayerSprite` line 201 of the handler dump),
   `.GetRopeHeight`/`.GetRopeBridgeHeight`, `.SuperSpring` (96 lines, from `.HitBackgroundSprite`),
   `.FootPressure` (89 lines, from `.HandleKeys` and `.HandleBoxSprite`), `.PlatformBounce`
   (95 lines, called from 19 `Hit*Sprite` routines incl. `.HitPlayerSprite`), `.HandlePlatformSprite`
   (761 lines) / `.DoSetupPlatformSprite` (488), `.HandleProgrammedPath` (81; Background, Bat,
   Gremlin), `.HandleFlotation @ 10042d04` (buoyancy for sprites with `s+0x19e > 0`: `vy ±=
   min(s+0x19e, 0x15e)`, then `vy ×= 0.93` or `0.86` — doubles `0x100a17f0`/`0x100a17f8`, read with
   `tools/const.py` — snap when `|vy| < 0x46`; gated in `.HandleUnderWater`),
   `.CheckGroundCeilingHitEffects`, `.HandleBreathing @ 1004bb44` (breath-sound cadence; 600 cap,
   floats 400/220 at `0x100a1a44/0x100a1a40`). Ropes, springs, platforms and pressure plates are
   core movement for a replica; NOT-RESOLVED item 6 covers only enemy handlers.
   (Command: `find_func.py '_RopeCollide\(' --names` etc. on both dumps; `grep -c` over `docs/ferazel/*.md` = 0 for each.)

3. **Important · confidence HIGH** · `spells-items.md` §2 items 3/7 and §2.1 "Statue" evidence;
   `physics.md` §0 (`+0x04 type`).
   Bank: shots are spawned with `type = spellId·256 + power` and enemies react to "shot type 1".
   Found: `.SetupPlayerShotSprite @ 1005925c` immediately rewrites the field —
   `*(uint *)(param_1 + 0x170) = type & 0xff; *(short *)(param_1 + 4) = type >> 8` — so `+4` holds
   the **spell id** and `+0x170` the power for the shot's whole life. All 12 `.TurnIntoStatue`
   sites test `*(short *)(param_2 + 4) == 1` (spell id), which a replica keeping `id·256+power` in
   `+4` would never satisfy. The rewrite (and `+0x170`) must be stated; §0's "+0x04 = type" needs
   the exception.
