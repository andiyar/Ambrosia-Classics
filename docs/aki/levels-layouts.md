- `x`, `y` are in **tile units with 0.5 resolution**. `_AddTile` stores `2x` at tile+0x10 and `2y` at
  tile+0x08 (internal "half-units"); everything downstream (open test, drawing, hit test) uses the
  half-unit values. [HIGH] — `*(double *)(g + 0x1d8) = param_1 + param_1;` → tile+0x10;
  `*(double *)(g + 0x1e0) = param_2 + param_2;` → tile+0x08 (`_AddTile` @ 0x146bc).
- `L` is the **source layer argument, 1 = top … 7 = bottom**. `_AddTile` stores `z = 7 − L`
  (the `if (param_3 == 0) param_3 = 6; else if (param_3 == 1) param_3 = 5; …` chain after
  `param_3 = param_3 + -1`), so stored z 0 = bottom, 6 = top. [HIGH]
- The per-level header gives the per-layout screen offset (g+0x94 subtracted from x pixels, g+0x98
  added to y pixels) and the background number g+0x8e, all read from the last three statements of
  each `_LayoutN` block. [HIGH]
- Tile order matters for the replica only in two places: the shuffle hands out faces in list order
  (`_ShuffleCustomTiles`) and the hint scans in list order (`_ShowNextCGHint`) — see `rules.md`.
